# 设计系统架构与维护规则

## 单一基础

组件行为统一使用 React 与原生 HTML；复杂浮层使用 Radix。不要在同一控件中混合 React Aria 与 Radix 的交互实现。Untitled UI 提供视觉与组织参考，shadcn/ui 提供可组合思路；0.2.0 已提供由源码生成的 shadcn Registry；安装方式见 registry.md。

Token 分为品牌、表面、文字、边框、状态、焦点、密度。组件使用语义变量，不在客户项目里硬编码品牌颜色。当前 CSS 是 Token 真源，JSON 由脚本生成；每次更改执行 `npm run tokens:sync`，一起提交 CSS 与 JSON。

## 场景边界

| 场景 | 推荐模式 | 需要业务层提供 |
| --- | --- | --- |
| 仪器软件 | 紧凑布局、固定单位、可辨认状态、键盘操作 | 设备连接、测量、校准、异常恢复 |
| 管理后台 | 设备表格、筛选、表单、确认弹窗 | API、权限、审计和分页 |
| 官网 | 舒适密度、大标题、响应式内容 | CMS、真实图片、SEO、国际化 |
| 客户定制 | 独立主题和配置 | 客户身份、功能权限、语言及业务字段 |

状态不得仅依靠颜色表达。测量数据必须同时说明单位、时间、精度与无效值；不要将断连显示成 0。声压级、加权方式、频率范围等由真实采集协议确定；示例读数不是产品规格。热力图/声学图谱需要独立色标，不能套用成功/危险色作为物理测量范围。

## 客户扩展

在目标项目增加独立样式文件，以 `html[data-customer="customer-id"]` 作为作用域，覆盖品牌色、hover、前景和焦点色，并分别验证明暗模式。不要复制基础组件。客户专用流程放在业务项目；经至少两个产品验证的模式再回收到本系统。

```css
html[data-customer="example"] {
  --cs-brand: #1857b6;
  --cs-brand-hover: #12458f;
  --cs-on-brand: #ffffff;
  --cs-focus: #1857b6;
}
```

当前支持固定 CSS 主题；不接受未经校验的用户输入注入 CSS。普通文本对比度目标 4.5:1，控件与焦点目标 3:1；每个新主题需要人工视觉与对比度复核，当前交互测试不等同于完整 WCAG 合规认证。

## 版本与交付

采用语义版本。新增兼容属性为 minor，修复为 patch，删除属性或 Token 为 major。每次发布先通过 `npm run check`，在消费项目验证安装包，再创建版本标签和变更说明。初期使用私有 GitHub 源码与 tarball 分发；GitHub Packages/npm 私有包发布需明确包命名空间和访问权限后配置。

新增组件要有类型、示例、键盘操作、禁用/加载/错误/空状态及适当测试。不要把硬件通信、鉴权、服务端数据请求塞进 UI 包。

## 基础空间约束

间距采用 tokens.css 的 cs-space 刻度：4px基线与2px半步（0、2、4、6、8、10、12、14、16、20、24、28、32等）。margin、padding、gap、浮层间隔、焦点偏移不使用奇数或小数像素。普通间距优先引用对应语义空间变量。布局中大尺寸定位按结构尺寸约束，仍禁止奇数像素。边框细线、图标描边、字号/行高、阴影、容器尺寸与百分比属于各自规范，不当作间距批量替换。

styles:check 包含 validate-spacing.mjs，覆盖 packages/ui/src 和 apps/docs/src 的 CSS 声明、React 内联 style 字面值与浮层 sideOffset/alignOffset/collisionPadding。普通流布局96px以内的间距必须命中基础刻度，所有固定像素间距都检查奇数与小数。动态表达式仍需按空间变量编写并进行视觉验证。
